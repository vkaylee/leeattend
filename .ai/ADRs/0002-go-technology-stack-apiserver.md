# ADR 0002: Enterprise Go Technology Stack for LeeAttend API Server

Status: Accepted
Deciders: Platform Engineering, Backend Lead
Date: 2026-10-19

## Context and Problem Statement

The `apiserver` component is being migrated from Rust/Axum to Go.
The primary risk is uncontrolled behavioral divergence, type drift, and hidden runtime regressions ("AI làm ẩu").
To prevent this, every layer of the Go stack must be verifiable through automated, reproducible compile-time and runtime checks. Handlers, database queries, and API models must fail compilation rather than rely on manual review.

Attendance pairing and calculation logic is retained in-process within pure Go packages (`internal/domain/...`) rather than extracted to a separate service, eliminating RPC latency, network failure modes, and distributed transactions.

## Decision Drivers

1. **Compile-Time Contract Enforcement:** Handlers must implement a strictly-typed Go interface generated directly from the canonical OpenAPI spec. Omitting a route, returning an unmapped type, or altering a parameter must break the build.
2. **Deterministic Database Operations:** Zero ORM magic. Queries must be explicit SQL verified against the active PostgreSQL schema, with parameter and result types generated at build time. Tenant isolation (`workspace_id`) must be directly visible in every query.
3. **Arbitrary-Precision Arithmetic:** Payroll, overtime, and leave balance calculations must use exact fixed-point decimals. Binary floating-point (`float64`) is strictly forbidden for financial and hour values.
4. **Zero-Overhead In-Process Computation:** Attendance pairing, matching, timezone adjustment, and DST resolution remain in-process pure functions with no network, DB, or global state dependencies.
5. **Standard-First Architecture:** Prefer Go standard library (`net/http.ServeMux`, `log/slog`) over third-party framework sprawl. Every third-party library introduced must solve a concrete, verified need that the standard library cannot fulfill safely.
6. **Reproducible Automated Verification:** All builds, linters, tests, and coverage checks must run inside a hermetic container and fail closed.

## Selected Stack Specification

### 1. HTTP Layer: `net/http.ServeMux` + `oapi-codegen` Strict Server

- **Choice:** Standard library `net/http.ServeMux` using Go 1.22+ method-and-path patterns (`GET /v1/workspaces/{id}/employees`).
- **Contract Enforcement:** `oapi-codegen` v2 generates a `StrictServerInterface` from the canonical OpenAPI specification. Handlers implement this interface:
  ```go
  type StrictServerInterface interface {
      ListEmployees(ctx context.Context, request ListEmployeesRequestObject) (ListEmployeesResponseObject, error)
      // Every route from OpenAPI is a compile-time method requirement
  }
  ```
- **Why this wins:** If an engineer or AI forgets a route, alters a parameter type, or returns an unmapped status code, **the Go compiler rejects the build**. No router framework (Chi/Gin/Echo) is needed because routing patterns are native since Go 1.22, and the strict server adapter wraps the standard mux directly.

### 2. Database Layer: `pgx/v5` + `sqlc` (No ORM)

- **Choice:** `pgx/v5` connection pool with `sqlc` query compiler.
- **Contract Enforcement:** `sqlc` reads the existing PostgreSQL migrations and raw `.sql` query files, generating type-safe Go structs and query functions:
  ```go
  // Generated by sqlc from: SELECT ... WHERE workspace_id = $1 AND id = $2
  func (q *Queries) GetEmployee(ctx context.Context, arg GetEmployeeParams) (Employee, error)
  ```
- **Why this wins:**
  - **Zero N+1:** Queries are explicit SQL; no hidden lazy loading or magic relationship hydration.
  - **Compile-Time SQL Validation:** `sqlc compile` validates syntax, column names, and types against PostgreSQL schema before code runs.
  - **Tenant Isolation:** Every tenant query explicitly binds `workspace_id`. Missing `workspace_id` is caught during SQL review, not at runtime.
  - **Transaction Safety:** Transactions use explicit `pgx.Tx` with scoped commit/rollback deferrals.

### 3. Financial & Attendance Arithmetic: `shopspring/decimal`

- **Choice:** `shopspring/decimal` arbitrary-precision fixed-point decimal.
- **Rule:** `float32` and `float64` are **prohibited** for monetary amounts, overtime hours, leave accruals, and salary components.
- **Why this wins:** Matches Rust's `rust_decimal::Decimal` and `bigdecimal::BigDecimal` guarantees. Eliminates binary floating-point rounding errors (e.g., `0.1 + 0.2 != 0.3`) in payroll calculations.

### 4. Domain Calculations: Pure In-Process Packages

- **Choice:** Pure Go packages under `internal/domain/pairing`, `internal/domain/matcher`, and `internal/domain/payroll`.
- **Invariants:**
  - Zero imports of `database/sql`, `pgx`, Redis, or HTTP clients.
  - Zero wall-clock reads (`time.Now()` must be passed in as parameter).
  - Zero global state or mutable package-level variables.
  - Deterministic input snapshot in, deterministic result out.
- **Why this wins:** Eliminates network serialization overhead, gRPC tooling complexity, mTLS certificate management, and distributed failure modes. Parity with Rust is proven via identical table-driven test fixtures.

### 5. Observability: `log/slog` + OpenTelemetry Go

- **Choice:** Standard library `log/slog` with JSON handler, plus OpenTelemetry Go SDK.
- **Invariants:**
  - Mandatory fields: `timestamp`, `level`, `service`, `request_id`, `workspace_id` (when in tenant context).
  - PII masking: T1 data strictly omitted, T2 data masked via centralized handler.
  - Request ID: extracted/generated at edge middleware, propagated via `context.Context`.

### 6. Verification & Quality Gates

Every Go build must pass all gates in a hermetic container:

```bash
# 1. Format
test -z "$(gofmt -l .)"

# 2. Compiler & type checker
go vet ./...

# 3. Static analysis (bugs, performance, style)
staticcheck ./...

# 4. Known vulnerability scanner
govulncheck ./...

# 5. Dependency verification
go mod verify

# 6. Generated code freshness (fail if generated code differs from repo)
sqlc generate && git diff --exit-code internal/db/
oapi-codegen ... && git diff --exit-code internal/api/

# 7. Unit tests with race detector
go test -race -cover ./...

# 8. Parity differential tests
go test ./tests/parity/... -run TestParity
```

## Consequences

### Positive
- Type safety is enforced by compiler (`oapi-codegen` strict server + `sqlc`), preventing hallucinations from compiling.
- Zero runtime ORM overhead and zero implicit queries.
- Architecture is simpler without an external compute service (single deployable binary).
- Standard library foundation reduces external dependency supply-chain risks.

### Negative / Trade-offs
- Writing raw SQL with `sqlc` requires more upfront query authoring than ORM methods.
- Strict server interface requires explicit mapping for every route; cannot "stub out" routes partially.
- Regenerating code after schema or OpenAPI changes requires running the generator toolchain.
