## 1. Executive Summary & Core Invariants

The `apiserver` error system is centered on the `AppError` enum (`apiserver/src/errors.rs:48-84`) and its `IntoResponse` implementation (`apiserver/src/errors.rs:362-405`).

### Inviolable Wire Contract Rules
1. **JSON Envelope Structure:** Every API business error generated by `AppError::into_response` serializes as a single top-level JSON object with an `"error"` wrapper:
   ```json
   {
     "error": {
       "code": "<ERROR_CODE>",
       "message": "<LOCALIZED_OR_COMPOSED_MESSAGE>"
     }
   }
   ```
2. **Conflict Retry Extension:** When `AppError::Conflict` carries a structured retry hint (`Option<serde_json::Value>`), the envelope adds a `"retry"` property at `error.retry`:
   ```json
   {
     "error": {
       "code": "CONFLICT",
       "message": "<LOCALIZED_MESSAGE>",
       "retry": { ... }
     }
   }
   ```
3. **No Top-Level or Array `field_errors` in AppError:** `AppError` does **not** emit a `field_errors` array or object. Field validation failures compose directly into the `"message"` string (e.g. `"<translated_prefix>: <details>"` via `LocalizedMessage::KeyWithArgs`). Structured row errors exist exclusively inside specific endpoint business payloads (e.g. `BulkOtUploadResult.errors`).
4. **Internal Error Masking:** All internal server errors (`DATABASE_ERROR`, `REDIS_ERROR`, `INTERNAL_ERROR`, `BACKGROUND_JOB_ERROR`, `TEMPLATE_ERROR`) **never** expose internal root causes or SQL/Redis details to the HTTP client. The wire message is unconditionally translated from `error.internal`.
5. **Two Non-JSON Exceptions:**
   - Primitive auth extractor failure (`UserId::from_request_parts`, `apiserver/src/lib.rs:164`): HTTP `401 Unauthorized`, `Content-Type: text/plain; charset=utf-8`, body `"Authentication required"`.
   - Transport / Axum deserialization errors before reaching handlers (e.g. malformed JSON syntax, route param parse failure): HTTP 400/413/415/422 with `text/plain` bodies.

## 5. Message Localization Rules & Resolution Pipeline

Message translation is governed by `apiserver/src/utils/i18n.rs` and `apiserver/src/errors.rs:316-359`.

### 5.1 Locale Resolution Order
1. **Query parameter:** Inspects URL query string for `?lang=<value>`. Parses `"vi"`, `"en"`, or `"zh"` (case-insensitive, trims).
2. **`Accept-Language` header:** Evaluates comma-separated language tags (e.g. `vi-VN,vi;q=0.9,en-US;q=0.8`). Takes the first matching language tag.
3. **Default fallback:** `"vi"` (Vietnamese).
4. **Context storage:** Bound to Tokio task-local `CURRENT_LOCALE` (`i18n.rs:248`). If unbound (e.g. background worker), defaults to `"vi"` (`i18n.rs:255`).

### 5.2 Translation Fallback Chain
For any key `k` and requested language `lang`:
1. Look up translation in `lookup_<lang>(k)`.
2. Fallback to Vietnamese: `lookup_vi(k)`.
3. Fallback to English: `lookup_en(k)`.
4. Fallback to raw canonical key string: `k` (e.g. `"error.workspace_not_found"`).

### 5.3 Composed Arguments (`LocalizedMessage`)
- **No arguments (`LocalizedMessage::Key`):** Returns translated string directly.
- **With arguments (`LocalizedMessage::KeyWithArgs`):**
  - **`details` convention (`errors.rs:331-336,346-351`):**  
    If an argument named `"details"` is present:
    - If translated prefix equals the raw key or is empty: returns `details_value`.
    - Otherwise: returns `format!("{translated_prefix}: {details_value}")`.
  - **Template placeholder convention (`i18n.rs:284-301`):**  
    Substitutes named placeholders: `{name}` is replaced with the matching argument value.

## 8. Client & Server Retryability Matrix

Rust `AppError` has **no retry classifier and no `Retry-After` header** for any variant (`apiserver/src/errors.rs:362-405`). The only server-emitted retry header in the API is the rate limiter's `Retry-After` (`apiserver/src/mw/rate_limit.rs:214`). Retry behavior elsewhere is either frontend policy (`webdashboard/src/lib/api/`) or a separate agent/worker delivery-state contract (`apiserver/src/worker/ack_sink.rs:5-10`). Rows marked **UNKNOWN** MUST NOT be decided silently.

| Scenario / Code | HTTP Status | Client Response Header | Frontend / Consumer Behavior | Backoff Recommendation |
|---|---|---|---|---|

| **Rate Limit Exceeded (`RATE_LIMITED`)** | `429` | `Retry-After: <window_secs>` (`rate_limit.rs:212-220`) | Client SHOULD wait until `Retry-After` seconds elapse before repeating request. | Fixed limiter window; default is config-derived, not hard-coded here (`rate_limit.rs:83-96`). |
| **Account Lockout (`TOO_MANY_REQUESTS`)** | `429` | None | Client receives translated lockout message. | Lockout TTL is set to 900 seconds when first attempt is recorded (`auth.rs:175-178`); automatic retry behavior is not specified. |
| **Expired JWT (`UNAUTHORIZED`)** | `401` | None | Frontend may invoke `POST /api/v1/auth/refresh` and retry once (`webdashboard/src/lib/api/api-fetch-helpers.ts:24-104`). | Frontend policy, not AppError policy. |
| **Soft Compliance Conflict (`CONFLICT`)** | `409` | None | Frontend may inspect `error.retry` and resubmit after confirmation (`webdashboard/src/lib/api/errors.ts:30-54`). | No automatic retry; user override required (`compliance_validation_service.rs:198-215`). |
| **Retired Leave Type Conflict (`CONFLICT`)** | `409` | None | Frontend may inspect `error.retry` (`webdashboard/src/lib/api/errors.ts:56-77`). | No automatic retry; restore choice required. |
| **Service Unavailable (`SERVICE_UNAVAILABLE`)** | `503` | None | No Rust/frontend automatic retry rule found. | **UNKNOWN — no AppError retry classifier or `Retry-After`; Go MUST NOT invent one without decision.** |
| **Worker Queue Ingestion (`retryable_error`)** | WS Frame (`apiserver/src/worker/ack_sink.rs:5-10`, `apiserver/src/handlers/agents.rs:275`) | None | Agent resets message locally via `reset_to_unsynced_by_msg_id` (`agent-main/src/central_client/message_handler.rs:185-196`) and retries sync. | Stateless exponential backoff ($2^{\text{retry\_count}}$ or $5 \times 2^{\text{retry\_count}}$, capped at 60s/300s, `agent-main/src/redb_store/attendance_ops.rs:388-393`). |
| **Permanent Client Error (`VALIDATION_ERROR`, `FORBIDDEN`, `NOT_FOUND`, `PAYLOAD_TOO_LARGE`)** | `400`, `403`, `404`, `413` | None | No automatic retry rule is emitted by Rust. | Change request/permission/size before retry; exact client policy is not encoded in `AppError`. |

## 9. Go Target Implementation Architecture

To guarantee exact parity with Rust's `AppError` without framework overhead:

### 9.1 Target Package: `internal/apperror`
```go
package apperror

import (
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"log/slog"
	"net/http"
)

type ErrorCode string

const (
	CodeDatabaseError      ErrorCode = "DATABASE_ERROR"
	CodeRedisError         ErrorCode = "REDIS_ERROR"
	CodeUnauthorized       ErrorCode = "UNAUTHORIZED"
	CodeForbidden          ErrorCode = "FORBIDDEN"
	CodeNotFound           ErrorCode = "NOT_FOUND"
	CodeValidationError    ErrorCode = "VALIDATION_ERROR"
	CodePayloadTooLarge    ErrorCode = "PAYLOAD_TOO_LARGE"
	CodeInternalError      ErrorCode = "INTERNAL_ERROR"
	CodeConflict           ErrorCode = "CONFLICT"
	CodeServiceUnavailable ErrorCode = "SERVICE_UNAVAILABLE"
	CodeBackgroundJobError ErrorCode = "BACKGROUND_JOB_ERROR"
	CodeTemplateError      ErrorCode = "TEMPLATE_ERROR"
	CodeRateLimited        ErrorCode = "RATE_LIMITED"
	CodeTooManyRequests    ErrorCode = "TOO_MANY_REQUESTS"
)

// AppError is the canonical application error type matching Rust AppError.
type AppError struct {
	Code        ErrorCode
	Status      int
	I18nKey     string
	Args        map[string]string
	Retry       any
	InternalErr error
}

func (e *AppError) Error() string {
	if e.InternalErr != nil {
		return fmt.Sprintf("[%s:%d] %s: %v", e.Code, e.Status, e.I18nKey, e.InternalErr)
	}
	return fmt.Sprintf("[%s:%d] %s", e.Code, e.Status, e.I18nKey)
}

func (e *AppError) Unwrap() error {
	return e.InternalErr
}

// WireErrorEnvelope represents the exact serialized JSON structure.
type WireErrorEnvelope struct {
	Error WireErrorBody `json:"error"`
}

type WireErrorBody struct {
	Code    ErrorCode `json:"code"`
	Message string    `json:"message"`
	Retry   any       `json:"retry,omitempty"`
}
```

### 9.2 Centralized HTTP Error Responder (`WriteError`)
```go
func WriteError(w http.ResponseWriter, r *http.Request, err error) {
	var appErr *AppError
	if !errors.As(err, &appErr) {
		appErr = &AppError{
			Code:        CodeInternalError,
			Status:      http.StatusInternalServerError,
			I18nKey:     "error.internal",
			InternalErr: err,
		}
	}

	// 1. Log internal errors at slog.LevelError
	if appErr.Status >= 500 {
		slog.ErrorContext(r.Context(), "Internal API Error",
			"error", appErr.InternalErr,
			"code", appErr.Code,
			"status", appErr.Status,
		)
	}

	// 2. Resolve request language via context
	lang := GetLocale(r.Context())

	// 3. Translate message
	var message string
	if appErr.Status >= 500 {
		message = Translate(lang, "error.internal")
	} else {
		message = FormatMessage(lang, appErr.I18nKey, appErr.Args)
	}

	// 4. Construct wire payload
	resp := WireErrorEnvelope{
		Error: WireErrorBody{
			Code:    appErr.Code,
			Message: message,
			Retry:   appErr.Retry,
		},
	}

	// 5. Emit response
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(appErr.Status)
	_ = json.NewEncoder(w).Encode(resp)
}
```

## 10. Audit Findings & Ambiguity Ledger

1. **Plain-Text 401 on Primitive Auth Extractor:**  
   - Citation: `apiserver/src/lib.rs:164`.  
   - Observation: When `UserId::from_request_parts` fails, Axum returns HTTP 401 with plain-text `"Authentication required"`. When `SystemContext` or domain endpoints fail auth, they return JSON `{"error": {"code": "UNAUTHORIZED", "message": ...}}`.  
   - Rule: Go `auth` middleware MUST preserve this distinction: primitive JWT rejection sends `"Authentication required"` (text/plain) while domain auth errors send standard JSON envelopes.

2. **Absence of Top-Level `field_errors`:**  
   - Citation: `apiserver/src/errors.rs:388-402`.  
   - Observation: The Rust server has no per-field validation error collection in `AppError`. Field validation errors compose formatted strings in `"message"`.  
   - Rule: The Go server MUST NOT add unrequested field error wrappers or invent alternative JSON schemas. Parity requires keeping the exact `{ "error": { "code", "message" } }` schema.

3. **Status Code 422 Conversion:**  
   - Citation: `apiserver/src/errors.rs:129-144,292`.  
   - Observation: `AppError::from((StatusCode::UNPROCESSABLE_ENTITY, msg))` maps HTTP 422 to `AppError::Validation`, which then returns HTTP 400 Bad Request on wire serialization. Axum's raw JSON deserializer (`JsonDataError`) returns HTTP 422 with a plain-text error.  
   - Rule: Go request decoders should preserve HTTP 400 for domain validation errors and HTTP 422 only when strict JSON body decoding fails prior to handler invocation.

4. **Unknown Items:** **NONE**. All 12 `AppError` variants, 152 translatable `I18nKey` entries, status mappings, logging classifications, and retry policies have exact file and line citations in `apiserver/src`.
